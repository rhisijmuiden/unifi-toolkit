# Translations (English and Dutch)

English is the source language. Pick **Nederlands** or **English** in the left menu; the choice is kept per browser (`localStorage` key `unifi-toolkit-lang`, plus a `toolkit_lang` cookie for the server).

## How it works

The tools render English from Jinja templates and from Alpine/vanilla JS, so instead of rewriting every template the page is translated in the browser by `app/static/i18n/i18n.js`:

- Every text node and the `title`, `placeholder`, `aria-label` and `alt` attributes are looked up in the dictionary for the chosen language. The key is the English text with whitespace collapsed and trimmed.
- If there is no exact match, the `patterns` (regular expressions over the whole text) are tried, for text with numbers or names in it.
- A `MutationObserver` keeps text that appears later (tables, toasts, modals, Alpine bindings) translated, and `confirm()` / `alert()` messages go through the dictionary too.
- Anything inside `script`, `style`, `code`, `pre`, `textarea` or an element with `data-no-i18n` is left alone.

## Adding or fixing a translation

Edit `app/static/i18n/nl.js` and add `"English text": "Nederlandse tekst"` to `strings`. Copy the English exactly as it shows on the page (one text node: if a sentence is split by a link or `<strong>`, each part is its own key). Bump the `?v=` on the script tag in `app/templates/shared/_brand_head.html` so browsers fetch the new file.

When you add UI text to a template or script, add its Dutch translation in the same change.

## Adding a language

Copy `nl.js` to `<code>.js`, register it as `window.TOOLKIT_I18N.<code>`, add it to `LANGS` in `i18n.js` and include the script in `_brand_head.html`.
